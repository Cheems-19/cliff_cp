## 9. Reproducibility statement（可复现声明）

> **Reproducibility**
>
> All random seeds are fixed and reported. Coverage backtests are reported with the correct split-level framing (the binomial null is not valid within a single split). No result depends on a threshold chosen after seeing outcomes: the pre-registered analysis plan (`预注册_分析计划.md`, mirrored in SI §S7) fixes the primary/secondary hypothesis split, the Holm–Bonferroni correction within the primary family, and the direction-consistency criterion. Deviations and post-hoc additions are logged in the plan's "changes outside this plan" table.

| 类型 | 出现位置 | 处理 |

用配套脚本自查（只报告、不改动）：

```bash
python release/sanitize_check.py            # 扫描当前项目

```

**⚠️ 提交前务必人工复核一遍 `--fix` 的结果**：自动替换可能改到日志/结果文件里本来就有意义的字符串。

## 12. 一次性发布流程（建议顺序）

1. 填完 §0 的 11 个字段；
2. `python release/sanitize_check.py --fix` → 人工复核；
3. 按 §10 整理目录，按 `release/.gitignore` 排除；
4. `git init` → 首次提交 → 推到 GitHub（先设为 **private**，边写边提）；
5. 把 `release/CITATION.cff` 的作者字段填好（GitHub 会据此生成"Cite this repository"）；
6. 在 Zenodo 里关联该 repo → 创建 GitHub Release（tag 如 `v1.0-submission`）→ **Zenodo 自动发 DOI**；
7. 把 DOI 回填到 §5/§6 与正文的 Data & code availability；
8. 投稿前把 repo 转 **public**（或按刊要求保持匿名副本）。
